# Kansoku 桌面版

个人交易日志的图表看板，打包成 macOS 桌面 app（`Kansoku.app`），本地跑内核和
图表 UI，不需要开着终端敲命令。

## 下载与安装

去 [Releases 页面](https://github.com/Innei/kansoku/releases) 下载最新一个
`desktop-v*` 版本的 `Kansoku-x.y.z-arm64.dmg`，双击挂载，把 `Kansoku.app`
拖进「应用程序」文件夹。目前只发 Apple Silicon（arm64）版本。

## 首次打开：绕过 Gatekeeper 的"应用已损坏"提示

这个 app 没有走 Apple 付费开发者账号签名（只做了本地 ad-hoc 签名），第一次打开
macOS 会拦一下，提示"无法打开，因为无法验证开发者"或"应用已损坏，无法打开"。这不
是真的损坏，按下面步骤操作一次就好，以后正常双击打开：

1. 在「应用程序」文件夹里找到 `Kansoku.app`，**不要双击**，改成右键（或
   `control` + 单击）。
2. 菜单里选「打开」。
3. 会弹出一个新的确认框（这次带了「打开」按钮），点「打开」。
4. 之后这个 app 再双击就能正常打开，不会再拦。

如果这一步之后还是提示"已损坏"，去「系统设置 → 隐私与安全性」页面往下翻，看看
有没有一条"Kansoku 已被阻止使用"，点旁边的「仍要打开」。

## 配置 Longbridge 凭证

图表数据靠 Longbridge 的行情接口拉取。推荐直接用长桥账号登录：

- 首次打开会看到引导页，点「用长桥账号登录」，会弹出浏览器完成授权，授权成功
  后自动进入正常界面，不需要手动填任何字段。
- 之后凭证会加密保存在本机并自动续期；想换账号或清除，去「设置」页的 Longbridge
  凭证卡片操作。

也可以手动填一套接口凭证（app key / app secret / access token），适合不想走
浏览器授权的场景：

- 申请入口：<https://open.longportapp.com>，用你的长桥账号登录后创建应用。
- 拿到三个字段后，在引导页或「设置」页展开「手动填写 API 凭证（高级）」填入并
  保存即可，不需要重启 app。

## 外部 API 开关（进阶）

「设置」页有一个"外部 API"开关，打开后会在本机起一个带随机 token 的本地 HTTP/WS
服务（默认监听 `127.0.0.1`，不对外网暴露），方便用脚本或其他工具读取图表数据、
订阅实时行情。不需要这个功能的话保持关闭即可，默认就是关闭状态。

## 应用菜单

菜单栏（macOS 顶部）大致是：

| 菜单                  | 常用项                                                                 |
| --------------------- | ---------------------------------------------------------------------- |
| **Kansoku**（应用名） | 关于、检查更新…、显示 Agent Workspace…、导入 Kansoku 数据…、设置、退出 |
| **编辑**              | 撤销/复制/粘贴等系统能力                                               |
| **显示**              | 刷新、缩放、全屏、开发者工具                                           |
| **窗口**              | 新建/关闭/切换标签页（⌘T / ⌘W / ⌘⇧] / ⌘⇧[）、最小化                    |

- **设置…**：打开或聚焦设置标签页（和标题栏齿轮同一条路径）。
- **检查更新…**：打包版会走 Sparkle 或 GitHub 弱检查；开发模式（`pnpm dev:desktop`）只会提示「开发模式不检查更新」。
- **显示 Agent Workspace…**：在 Finder 打开 App 和纯 Agent 共用的用户文件目录。
- **导入 Kansoku 数据…**：见「导入现有数据」一节。

## Agent Workspace 与本地 State

打包版不再允许把整套数据切换到任意目录。用户文件和本地数据库分开存放：

```text
~/Library/Application Support/Kansoku/
  Workspace/
    journal/               # 研究、图表 JSON、画布
    stocks/                # 股票笔记
    .kansoku-agent-kit/    # Agent Kit 运行入口
  State/
    app.db                 # 本地 SQLite，不进入 iCloud Drive
```

设置页只显示完整路径和「在 Finder 中显示」，不再有目录选择器。这样 App、Agent Kit 和
`kansoku-cli` 永远指向同一份 Workspace / DB，不会因为切换项目根而看见另一套空数据。

### 为什么以前能选择目录，现在删除了

Kansoku 最早是一组 trade skills，App 是后来的宿主。旧设计让安装版绑定项目目录，是为了
让 Codex / Claude Code 在项目里直接读写与 App 相同的数据。但它也把用户文件、SQLite、
凭证和项目生命周期绑在一起：换路径像换账号，同时运行还会争用同一个数据库。

现在由固定 Agent Workspace 承接原本目标：直接把它作为 Agent 项目打开，就能使用内置
skills、读写 `journal/` / `stocks/`，并通过 CLI 操作同一个本地数据库。Agent Kit 仍可
安装到另一个代码项目，但 `runtime.env` 会把数据输出明确路由回 Agent Workspace。

### 从旧版本自动迁移

首次升级会在内核和数据库启动前执行一次复制迁移：

- 旧自定义目录与旧默认目录的 `journal/**`、`stocks/**` 都会复制；
- 自定义目录版本为主，同名不同内容会生成冲突副本，不静默覆盖；
- SQLite 用在线 backup 生成一致快照，不直接复制 WAL 文件；
- 旧目录不可访问时会阻止空数据启动，让用户重新定位或明确选择本次空 Workspace；
- 完整性检查通过后才写完成标记并移除旧 `data-root.json`；
- 旧自定义目录和其中内容不会自动删除。

迁移进度位于 `State/storage-migration-v1.json`，中断后可安全重试。

### Pro iCloud

Pro 设置可把整个 Agent Workspace 迁入 Kansoku 的 iCloud container。切换成功后业务文件
只以 iCloud Workspace 为工作副本，原本机 Workspace 移入废纸篓；SQLite 仍留在本机
`State/app.db`，选定的耐久记录通过 CloudKit private database 同步。

许可证到期时不会切回空本地目录：iCloud 文件保持可读写，CloudKit 记录同步暂停。设置页的
公共恢复按钮可把 iCloud Workspace 安全复制回本机，iCloud 原文件不删除。

### 进阶：环境变量覆盖

`TRADE_PROJECT_ROOT` 和 `KANSOKU_DB_PATH` 只保留给开发、Server 与自动化，不是设置页
产品功能。普通用户不需要设置。

## 导入现有数据

菜单「导入 Kansoku 数据…」可以把另一个旧目录或项目中的用户文件一次性合入当前
Workspace：

1. 选择包含 `journal/` 或 `stocks/` 的目录。
2. App 复制两棵目录里的普通文件，跳过符号链接和 SQLite/WAL。
3. 同内容文件跳过；同名不同内容保留为带哈希的冲突副本。
4. 任一文件失败都会报告，源目录不会删除。

导入不是持续同步，也不接管源目录；需要持续由 Agent 工作时，请直接打开 Agent Workspace。

## 更新机制

app 内置 Sparkle 自动更新：启动时和之后定期会静默检查有没有新版本，有的话会提示
下载安装。如果 Sparkle 检查因为某些原因没触发（比如网络问题），还有一层"弱更新
兜底"：app 会额外去 GitHub Releases API 查一次最新版本号，发现落后了会给一个不
强制、可以先忽略的提示条。两层加起来，正常使用下不需要手动去下载新安装包。

## 安全边界（Pro 功能加密）

个股自动跟踪、深度研究、研究库 AI 这三项付费功能的代码，在安装包里是加密的单文件（`pro.enc`），不是能直接解开 asar 就读到的明文 JS；没有有效授权码，这段代码在内存里都不会被解密执行。解密用的 key 由授权服务器在验证授权码通过后发放，不写进安装包也不进 git 仓库。

**这挡的是什么**：下载免费版的人解包 app 拿不到 Pro 源码；没有授权码，patch 一处判断也换不来 Pro 功能——因为代码本身根本没被解密加载，不存在"判断被绕过后代码还在"这回事。

**这不挡什么（如实说明，不夸大）**：key 最终会进入已激活用户机器的内存，解密执行；一个决心破解的付费用户 dump 内存后传播明文代码，结构上无法阻止——这不是本方案要解决的问题。免费安装包本身仍然携带这份加密字节（只是解不开），不是"激活后才下载"。

## FAQ

**打开是白屏，什么都没有？**
还没配 Longbridge 凭证不会导致白屏——首次打开会看到凭证引导页，不是空白页。真
遇到白屏，大概率是安装包没装完整或者进程没退干净，先完全退出 app（`Cmd+Q`，不
是关窗口）重开一次；如果还是白屏，试试重新下载 dmg 装一遍，反馈时带上具体版本号
方便排查。

**怎么更新到新版本？**
不用手动做什么，参考上面"更新机制"一节，正常联网使用会自动提示。实在等不及也
可以去 Releases 页面手动下载新 dmg 重新装一遍，装新版本会覆盖旧版本，数据不会
丢（数据存在系统的 app 数据目录下，不在 `.app` 包里）。

**AI 相关设置里有的 provider 显示"OAuth"登录，桌面版能用吗？**
可以，但目前桌面版对走 OAuth 登录方式的 provider（例如某些走网页授权的模型
服务）支持还比较有限，稳定可用的是 API Key 方式的 provider。如果某个 provider
在设置页一直显示未配置，优先确认它是不是 OAuth 类型，换一个支持 API Key 的
provider 通常能绕开。
