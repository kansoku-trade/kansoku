# 分批加减仓：仓位管理进入 episode 引擎

日期：2026-07-27
状态：设计待确认

## 1. 为什么做

盲盘训练器 M3 跑通之后，实际刷盘暴露出一件事：现在的下单是「三价填空 + 全进全出」，练的是「止损放哪」，练不到**仓位管理**——而后者是短线交易里和止损同等重量的判断。

用户要的动作很具体：**入全仓 / 入 1/2**，**平 1/2 / 平全部**，并且允许在持仓中**再加**。

这推翻了原设计 spec §14 的「明确不做：多笔持仓 / 分批加减仓（会失去三价强制，训练器退化为手感玩具）」。推翻是用户明确决定的。但那条理由需要更正：**分批本身不会失去三价强制**，会失去它的是去掉止损。本设计保留止损为必填，因此三价、R 计价、两条纪律闸全部存活。

## 2. 核心：仓位会变时，R 是什么

这是整个设计唯一真正难的地方。所有下游——净 R、最大浮盈回吐、计划盈亏比、TD-RR-01 的 1.5 下限、TD-EXIT-01 的 1R 判定——都以 R 计价。仓位一动，R 的定义就必须重新回答。

### 2.1 三个候选，选第三个

| 模型 | 做法 | 为什么不选 |
| --- | --- | --- |
| A 加权平均单仓 | 每次加仓重算平均入场价，R 跟着重算 | **R 会追溯性变化**：价格没动，你补了一笔，原本 +2R 的浮盈变成 +1.4R。数字没人能解释 |
| B 纯分笔 | 每笔独立计 R，各自成绩 | 每笔的 R 单位不同，加总没有意义，「本局净 R」失去口径 |
| **C 固定 R 单位 + 分笔损益** | **R 单位在首次成交时锁死；损益按笔（lot）结算** | 选它 |

### 2.2 模型 C 的定义

**R 单位（riskUnit）在第一次成交那一刻锁死，此后永不改变：**

```
riskUnit = |首次成交价 − 初始止损|      （价格单位）
```

这是「你第一次承担风险时，一份风险有多大」。它是尺子，尺子不能在量东西的过程中伸缩。

**每次入场产生一笔 lot：** `{ 成交价, 仓位系数, 时间 }`，仓位系数 ∈ (0, 1]，全仓 = 1。

**每次平仓按 FIFO 关闭 lot**，可跨多笔。已实现损益：

```
已实现 R = Σ (平仓价 − 该 lot 入场价) × 方向 × 该 lot 仓位系数 / riskUnit
```

**未实现 R**（当前价 P 下）：

```
未实现 R = Σ (P − 未平 lot 入场价) × 方向 × 该 lot 仓位系数 / riskUnit
```

**本笔交易的净 R = 已实现 R 之和**（全部平完时）。

### 2.3 这个模型的三个后果，都是想要的

**加仓会放大可能的亏损，而 R 单位不变。** 半仓进、被止损 = −0.5R；补到满仓再被止损 ≈ −1R 甚至更多（因为补的那笔入场价更差）。**「给亏损的仓位加仓」在成绩上会直接变贵**，这正是该被练到的教训。

**分批止盈会体现在净 R 上。** +2R 处平掉一半锁定 1R，剩下半仓回到成本价平掉，净 R = 1R。全拿到底可能是 0 或 4。两条路的差别第一次变得可测量。

**轻仓试错真的便宜。** 1/4 仓做错只赔 0.25R。仓位管理因此成为可练的技能，而不是一个不影响分数的装饰。

### 2.4 最大浮盈回吐怎么算

以**整笔交易的权益曲线**为准，不是只看未平部分：

```
每根 bar 的权益 R = 已实现 R + 未实现 R
mfeR = max(0, 权益 R 在本笔交易存续期内的最大值)
maeR = max(0, −权益 R 的最小值)
回吐 = mfeR − 最终净 R
```

**两者都是幅度，不带符号**（与既有引擎、schema 的 `minimum: 0` 一致）。本节初稿写的是「maeR = 最小值」，字面读会得到负数——那是笔误，不是设计。改动的是**测量对象**（整笔交易的权益曲线，而非仅未平部分），不是符号约定。

这样「+3R 时平掉一半，剩下的跌回成本」会如实显示为「最高到过 3R，最后拿到 1.5R，回吐 1.5R」。

## 3. 止损、盈亏平衡与两条纪律闸

**一个仓位一个止损**，作用于全部未平 lot。触发时全部未平 lot 以止损价平掉。

**盈亏平衡价 = 未平 lot 的加权平均入场价**（这是未平部分不赚不赔的价格）。加仓会移动它，减仓不会。

**TD-RR-01（盈亏比 ≥ 1.5）** 在**首次入场时**判定，用首次成交价与止损、目标。加仓不重新判定——加仓不是一次新的方向判断，是仓位调整。

**TD-EXIT-01（达 1R 后止损不得移回亏损区）** 判定口径：
- 「达 1R」= 权益 R（已实现 + 未实现）曾经 ≥ 1
- 「亏损区」= 止损落在**当前未平 lot 的加权平均入场价**的亏损一侧

加仓会把盈亏平衡价推向不利方向，因此**加仓后原本合规的止损可能变得不合规**。这是真实的：你加了仓，保本线就移动了。引擎在改单时判定，不追溯。

## 4. 引擎改动面

`packages/bench/src/episode/engine.ts`（公开仓，与 bench 的 AI 共用）

| 位置 | 改动 |
| --- | --- |
| `PositionState` | 新增 `lots: PositionLot[]`、`riskUnit: number`、`realizedR: number`；`entryPrice` 改为派生的加权平均；`initialRisk` 由 `riskUnit` 取代 |
| `submitEpisode` | 接受 `size`（默认 1） |
| `EpisodeTradeAction` | 新增 `add`（加仓，带 size）与 `reduce`（减仓，带 size）；`exit_next_open` 等价于 `reduce` 全部 |
| 成交路径 | 止损/目标触发时平掉全部未平 lot |
| `EpisodeClosedTrade` | 从「一进一出」变为「一组 lot + 一组平仓」 |

**AI 路径必须逐字节不变**：`size` 不传即 1，不调 `add`/`reduce` 时行为与今天完全一致。单 lot、单次全平的情况下 `riskUnit = |入场 − 止损|`、`净 R = (平仓价 − 入场价)/riskUnit`，与现有公式恒等。这是硬要求，用测试钉住——bench 的 AI 成绩已经因为 TD-EXIT-01 断代过一次，不能再断第二次。

## 6. 下单交互（同期改造）

按用户确认的方向，与本设计同批做：

- **撤掉三个数字输入框和多/空按钮**
- **图上一次拖拽定两条线**：按下 = 止损，松手 = 目标；拖拽方向穿过入场线决定多空（向上 = 多，向下 = 空）
- **入场价固定为当前价（市价）**，不可拖。**限价挂单从训练器移除**——这同时移除 spec §6 的「限价挂单、超时作废」，引擎的 `pending` 阶段在训练器里不再可达（bench 的 AI 仍在用）
- **仓位按钮**：入场做多/做空 · 全仓 / 1/2 / 1/4；持仓中：加仓 · 1/2 / 1/4，平仓 · 1/2 / 全部

## 7. 明确不做

- 每笔 lot 独立止损（一个仓位一个止损）
- 平仓时选择关闭哪一笔（固定 FIFO）
- 反手（平多直接开空）——先平后开，两笔交易
- 仓位以金额/股数计（只用满仓的分数）

## 8. 测试

- **AI 路径恒等**：单 lot 全平的 `riskUnit` / `netR` / `mfeR` / `maeR` 与改造前逐值相等。这条最重要
- **R 单位不随加仓改变**：加仓前后 riskUnit 恒定
- **加仓放大亏损**：半仓被止损 −0.5R；补满后被止损的绝对值更大
- **分批止盈**：+2R 平一半、余下回成本，净 R = 1R
- **回吐口径**：权益曲线的峰值减最终净 R
- **TD-EXIT-01 随盈亏平衡价移动**：加仓后原本合规的止损变为不合规
- **FIFO**：跨多笔 lot 的平仓按序关闭
