# 盲盘训练：历史 K 线实盘模拟

日期：2026-07-25
状态：设计已确认，待实现

## 1. 这是什么

一个人类版的 episode 交易训练器：随机抽一段被匿名化过的历史行情，你在不知道标的、不知道日期、看不见后面 K 线的前提下逐根推进、下单、止损止盈，跑完揭晓真身并复盘。

本质上是**把 bench episode 引擎前面的 AI 换成人**。同一套状态机、同一套匿名化、同一套成交规则。

定位是**个人训练场 + 复盘沉淀**，不做人机竞技排行榜。它同时是一个数据采集装置：训练中召唤 AI 陪练所产生的预测与人工标注，回流用于调优。

**全部功能属于 Pro。**

## 3. 时间周期：五档，只做短线

| 推进周期 | 根数 | 实际跨度 | 视图梯队 |
| --- | --- | --- | --- |
| 1m | ~180 | 约 3 小时（交易日内一段） | 1m / 5m / 15m |
| 5m | ~156 | 约 2 天 | 5m / 15m / 1h |
| 15m | ~78 | 约 3 天 | 15m / 1h / 日 |
| 30m | ~39 | 约 3 天 | 30m / 1h / 日 |
| 1h | ~63 | 约 9 天 | 1h / 日 / 周 |

**推进档与视图梯队是两回事**：只有表格左列五档可作为推进周期（即「你逐根点的那个周期」）；梯队里出现的「日」「周」仅作为上层参考视图，只能看、不能作为推进单位。

不做日线、周线**推进档**。原因见 §5：长跨度 case 无法排除消息面。

表中根数为默认值，应作为可配置参数，实测后调整。

1m 档不铺满两三天 —— 手动推进上千根不现实，它天然是「开盘后那一小时」这类局部战斗。1h 档反过来会超出三天，三天只有 21 根不够打。

### 数据可得性（M0 实测结论，2026-07-25）

**五档周期均可回溯至 2018 年初，池子的时间广度不受限。** 这推翻了设计初稿「分钟线只有几个月到一年」的假设。

实测（`longbridge kline history`，NVDA / AMD / MRVL / AEIS / CRUS）：

| 验证项 | 结果 |
| --- | --- |
| 1m / 5m / 15m / 30m / 1h @ 2018-01-02 | 全部有数据，均自开盘 14:30Z 起，根数与交易时长吻合 |
| 中小盘 5m @ 2019（AEIS / CRUS） | 390 根 = 5 日 × 78 根，完整 |
| 2020-03 熔断周 5m（NVDA） | 390 根完整 |
| 2022-06 熊市 15m（AEIS） | 130 根完整 |

因此 **2020 熔断、2022 熊市等极端行情均可做成 case**，训练不局限于常态市场。

个别标的在特定历史区间返回空（实测 SMCI @ 2019、ONTO @ 2019），原因是该标的当时未在主板交易或尚未成立，属标的生命周期问题而非数据深度问题。**采样阶段必须校验「该标的在该区间确实有连续数据」，空结果直接丢弃候选**，不可视为错误。

### 请求配额约束（影响 M2 实现）

- **单次请求上限 1000 根**，超出返回 `301607 request too many klines`
- `kline history` 在区间内根数超限时返回**区间末尾的 1000 根**，而非起始 1000 根
- 因此 case 生成必须**按时间窗口分页拉取并拼接**，不能一次请求覆盖整个区间
- `--session all`（含盘前盘后）覆盖约 12:20Z–次日 04:59Z，1m 单日接近或超过 1000 根 —— **该模式下连单日都需分页**

是否将盘前盘后纳入 case 由 M2 决定：纳入更接近真实日内交易（隔夜跳空、盘前异动都在），但数据量约为盘中的 2.5 倍。

## 5. case 池

### 采样

从标的池随机抽标的 + 随机抽历史起点。标的池以日均成交额门槛过滤（流动性差的图形不可信），基底名单从长桥拉取。

### 第一道闸：硬规则

不花 token、可复现。命中任一条即丢弃：

- 区间内有财报 —— `longbridge finance-calendar report`
- 区间内有 FOMC / CPI / 非农 —— `longbridge finance-calendar macrodata`
- 单日跳空超过阈值（跳空是消息面的指纹）
- 日均成交额低于门槛
- 区间波动率过低（死鱼盘：干净但没得练）

五档全部是短跨度（最长约 9 天），因此「排除财报与宏观事件」完全可行。这正是砍掉日线周线档的原因：周线 case 跨度一年必然包含四次财报，硬规则会把长周期 case 全数毙掉。

### 第二道闸：AI 精选

只对通过粗筛的候选运行。**输入是完整区间（含结局）** —— 上帝视角是必需的，否则无法判断这究竟是真突破还是假突破。

- 输入：完整区间数据 + 指标（复用 `chartPayload` / indicators）
- 输出：`worthy`（是否值得练）、`tag`（趋势跟随 / 回调买点 / 假突破 / 顶部反转 / 区间震荡）、`difficulty`
- **标签在训练过程中对用户隐藏，收盘才揭晓**

标签用途：选盘（「今天专练回调买点」）与统计（「你在假突破上胜率 23%」）。

AI 调用使用用户自己配置的 key。

### 匿名化与尾声段

过闸后运行 `anonymize`：换代号、平移日期、缩放价格，保留 provenance。

**同时生成尾声段**：case 结束之后约 50% 长度的后续走势，用**同一套变换参数**匿名化。尾声段只能在 case 生成时一起造，不能事后补 —— 价格缩放系数与日期平移量是 case 固有参数。

> **尾声段必须单独存文件，训练运行时不加载。** 它一旦混在 case 主体里，就是最直接的未来数据泄漏源。物理隔离，不依赖「记得别传」。

入池前运行 `audit.ts` 用实时长桥数据核对。

### 存储与补货

case 池落 JSON 文件（用户数据目录），与本仓「文件即数据库」一致，pro 侧当前未使用 sqlite。目录结构与训练记录一并规划，主体与尾声段分文件存放。

水位线机制：池子低于阈值时后台补货，复用 `memory/queue.ts` + `scheduler.ts`。用户点「来一盘」永远从池中秒抽，不等待生成。

以下阈值均为可配置参数，初值实测后确定：日均成交额门槛、单日跳空阈值、区间波动率下限、池子水位线、每档默认根数。

## 6. 训练局

### 交易动作

主体沿用 episode 引擎语义：入场 / 止损 / 目标三价必填、限价挂单、超时作废、持仓中可改止损目标、可下一根开盘平仓、单仓不可加减。

**新增一种成交方式：照现价立刻进**（止损与目标仍必填）。补上纯限价「眼看着走了没挂上」的憋屈 —— 真实盘里可以市价追，不该由工具替用户禁掉。引擎侧只需增加一种成交路径。

### 推进与播放

AI 是一根一决策，人经常连续多根不动作，没有播放功能会劝退。

**推进单位跟随当前视图周期。** 看 5m 图推一根即 5m；切到 15m 推一根即 15m —— 数据上是 3 根基础 K 线，引擎仍逐根结算，只是一次消费 N 根。

**视图周期只能等于或高于基础周期**，因为 case 不存在比基础更细的数据。这与 §3 梯队表一致（梯队恒为「该档 + 上层」）。

**对齐规则**：切到上层周期推进时，推进至下一根完整的上层周期边界，不允许停在半根上。

**两种操作**：

- 单根步进 —— 走一根当前视图周期
- 播放 —— 自动连续推进，倍速 0.5x / 1x / 2x / 4x / 8x（1x 的每根间隔实测手感后定）

倍速与视图周期是两个叠加的乘数：8x 叠加 1h 视图，一秒可消费数十根基础 K 线。因此有两条强制保护：

**保护一 —— 播放遇事件立即暂停。** 挂单成交、止损触发、目标达成、挂单超时作废，任一发生即停。否则仓位已经了结而用户毫无察觉，而「止损被打的那一刻」恰是最该观察的画面。

**保护二 —— 跨周期推进必须回溯步内事件。** 在 1h 视图推进一根等于走 12 根 5m，其间可能已成交又止损。引擎结算正确，但用户视觉上只见「跳了一下」。推进后须按序列出该步内部发生的事件（如「第 7 根 5m 触发挂单成交，第 11 根打到止损」），否则大周期推进等同蒙眼交易。

**大周期快进本身是一种风险行为** —— 为了快而放弃中间的观察权。这可被度量，见 §8 统计面板。

### 纪律拦截

训练器与玩具的分界。现有规则本只用于评 AI，此处同样约束人：

- **TD-RR-01** —— 盈亏比不足 1.5:1 时挂单按钮锁死，目标块变黄提示
- **TD-EXIT-01** —— 已达 1R 后不允许将止损移回亏损区

### 界面

布局沿用现有 `IntradayDashboard` 形态：左侧主图 + MACD 一列，右侧训练栏（状态 / 三价 / 下单 / 问 AI），底部推进控制，顶部周期切换。

**多周期靠切换而非同屏** —— 真实盯盘不可能三图同看，切换本身就是要练的动作。

**核心视觉约束：图永远只画到当前游标**，右侧未公开区域保持为雾。这是训练局与所有现有图表最根本的区别；`bench-report-ui` 的回放组件默认画全图，必须改造为游标截断。

### 下单交互

**图上拖拽 + 输入框微调，双向同步。** 拖动仓位框的绿/红边界调整目标与止损，盈亏比实时反馈；输入框同步显示并可精调。

选择拖拽而非纯输入的理由不是「更好用」：**拖拽强制你先在图上找到那个位置**，而敲数字可以随便填一个凑够 1.5:1 的目标价蒙混过关。训练器要练的恰恰是「止损该放哪」的判断。

## 7. AI 陪练与数据回流

### 锁定顺序（不可妥协）

**必须先提交自己的方向与三价，AI 的看法才解锁。**

若开局即可问 AI，训练退化为抄答案，标注也被锚定污染（「AI 说得对」变成「我俩想得一样」）。锁定顺序既保住训练价值，又使每条标注成为真正独立的第二意见 —— 正是 TD-VERIFY-01 要求的不自动同意。

它同时构成一个对照实验：可以统计「被 AI 说服改主意」与「坚持自己判断」的胜率差。

解锁后**手动触发、不限次数**，token 成本由用户自行掌握。

### 运行方式

复用现有预测 pipeline（`intraday-signal` 的多周期技术面读法），**无上帝视角**，输入严格限制在 B0 至当前游标。

**主要工程改造**：现有 pipeline 面向实时市场编写，自行拉取长桥、新闻、宏观。必须将数据获取抽成可注入接口。bench 的 episode runner 已为 AI 做过同样的事（`fetch_kline` 走引擎发的数据而非实时行情），照此实现。

因盘面已匿名化，AI 拿不到基本面与新闻，**只能纯技术面**。这与第一道闸已排除消息面驱动区间相匹配，是公平的。

### 打标：两层分工

- **自动判定（不需人工）** —— 结局已知，方向对错、入场是否触发、止损是否被打、目标是否达成，全部可算。
- **人工标注（只标机器算不出的）** —— 唯一值得人工的是「AI 的理由是否站得住」。方向蒙对不等于理由对：它说「回踩 20 周期均线获支撑」而价格根本没碰到那条均线，这种「结论对但理由错」只有人看得出，且它是最该修的毛病 —— 靠错误逻辑蒙对的下次必错。

**标注触发策略：只在自动判定为「方向对」时才请求人工标注。** 方向已经错的直接归档不问。把点击花在信息量最高处，一盘通常只问一到两条，长期标得下去。强制全标必然导致敷衍点击，敷衍数据比无数据更糟。

标注选项：站得住 / 结论对但理由错 / 不成立 / 跳过（跳过本身也记录，区分「未标」与「标了没问题」）。

### 回流用途

1. **改 prompt 与纪律规则** —— 统计出「假突破类 case 系统性偏多」这类偏差，直接回改 `trading-discipline` 规则或 agent prompt。见效最快。
2. **积累评测集** —— 刷过的 case 进 bench 成为回归测试。改完 prompt 跑一遍即知变好还是变坏。长期价值最高。

**不做**：few-shot 反例库（收益需大样本才显现）、fine-tune（本地无条件且不划算）。

## 8. 收盘、复盘与沉淀

### 收盘页

- **揭晓真身**：真实代号、真实日期、AI 打的标签与难度，一键跳转现有 symbol 页看真图（provenance 提供）
- **成绩**：每笔明细、净 R、**计划盈亏比 vs 实际拿到 vs 最大浮盈回吐**（这三个数最能照出人的毛病）
- **AI 对照**：本盘每次召唤的预测、自动判定结果、按 §7 策略请求的人工标注
- **教训输入**

### 复盘页

同一张图三段底色对应三种可见性：你打过的段 / 训练时被雾遮住的段 / 尾声段。

- 时间轴刷子可重放至任意一根，**图还原为当时所见**（右半边重新变回雾）
- 时间轴与图上标注操作事件：进场、止损、目标达成、AI 召唤、收盘
- 「显示收盘后走势」开关揭开尾声段
- 面板：强平后的最高／最低、若不平仓拿到尾声段末的结果、被止损那笔的超出幅度与之后是否到过目标

> **尾声段不进任何统计口径。** 「不平仓能拿 +3.6R」看多了会养成「死拿就赢」的错觉 —— 只看见这盘拿住能赢，看不见那些拿住会爆掉的盘。它用于观察结构，不用于计算成绩。

### 统计面板

- 总览：累计 R、胜率、计划盈亏比 vs 实际盈亏比
- 按结构标签分类的净 R 与胜率
- **止损体检**（实盘做不到）：被止损后价格最终仍达目标的比例、止损被打的平均超出幅度。实盘中被止损后没有平行世界，训练器有结局，能直接指出「方向对，输在止损贴太近」
- **AI 陪练影响**（训练器独有）：改主意后的胜率 vs 坚持自己判断的胜率
- **推进方式影响**：大周期快进期间持仓的胜率 vs 逐根推进期间的胜率 —— 度量「放弃观察权」的代价
- **AI 成绩单**：方向准确率、其中「理由站得住」与「结论对但理由错」的占比、按标签的系统性偏差

### 沉淀边界

- 结构化训练数据全部存于训练区，**不写入 `journal/`**
- 单盘复盘文章按需由 AI 现写，不落盘
- **唯一进入真实账本的通道**：某条教训经人工确认后写入 `journal/lessons.md`，并标明来源为训练盘

`lessons.md` 是短线预测前的必读清单，其价值来自「短且条条是真教训」。自动灌入会毁掉它。

## 9. 独立窗口与独立 entry

训练器运行在**独立窗口 + 独立 Vite entry**，不进主窗口标签系统。

现状澄清：`apps/web` 当前只有一个 `index.html`，现有 popout 是同一 SPA 的一条路由（`pages/popout/symbol`），并非独立 entry。「新窗口」与「新 entry」是两件事。

### 为什么必须独立 entry

1. **主窗口是活的** —— WS 实时行情推送、60 秒图表重建、通知、快捷键。训练窗口若活在同一 SPA 内，这些会持续打断训练。
2. **信息隔离**（更硬的理由）—— 主 SPA 内存中存有真实持仓、watchlist、实时报价。盲盘的前提是不知道标的，任何共享组件误读全局 store 即破功。独立 entry = 独立 JS 上下文，物理隔离，与尾声段单独存文件同一原则。

### 成本

同一 Vite 项目多 entry 可共享 `src/`，Rollup 自动拆公共 chunk，**图表组件无需抽成独立包**。需处理：

- 新增 `apps/web/train.html` 与对应入口模块
- `proLeakGuard` / `proOverlayPlugin` 覆盖新 entry
- Electron 侧经 `desktopWindowsBridge` 开指向该页面的 BrowserWindow
- 训练窗口不带标签栏，独立尺寸，可全屏

### 入口位置

- **命令面板**：`features/palette/commands.ts` 新增「开始盲盘训练」
- **首页卡片**：显示「池中 N 盘待打 / 上次成绩」，点击开窗。免费版可见但点击提示为 Pro —— 这是付费钩子
- **不进标签栏**

## 10. 数据流

```
生成期（后台）
  标的池 → 随机采样 → 硬规则闸 → AI 精选闸（上帝视角）
    → anonymize（主体 + 尾声段，同一套变换参数）
    → audit 核对 → 主体入池 / 尾声段单独存

训练期（训练窗口）
  抽 case（不含尾声段）→ engine 状态机逐根推进
    → 图截断至游标 → 人下单（拖拽三价，纪律拦截）
    → 锁定后手动召唤 AI（数据注入，无未来）

收盘期
  强平结算 → 揭晓 provenance → 加载尾声段
    → 自动判定 AI 预测 → 按策略请求人工标注
    → 结构化写入训练区 → 教训经确认写入 lessons.md
```

## 11. 错误与边界

- **case 生成失败**（数据缺口、audit 不通过）：丢弃该候选，补货流程继续，不阻塞用户
- **池子耗尽**：显示生成进度而非报错；允许用户指定周期档位优先补货
- **AI 陪练调用失败**：不影响训练继续，该次召唤不产生标注记录
- **训练中途关窗**：局面状态持久化，可恢复；恢复时不得因序列化往返而泄漏未公开数据
- **跨隔夜持仓**：不禁止。引擎跳空穿越规则已完备（止损跳空按更差开盘价、目标跳空按更优开盘价）。「设了止损却在开盘被跳穿」是必须亲身挨一次的教训，禁掉就学不到

## 12. 测试

- **引擎泛化**：五档周期各自的推进、梯队换算、`entryExpiryBars` 分档 —— 单元测试，复用 bench 现有 episode 测试结构
- **泄漏防护**（最关键）：断言训练运行时加载的 case 对象不含尾声段；断言 AI 陪练的数据包不含游标之后的 bar；断言图渲染数据在游标处截断
- **纪律拦截**：盈亏比边界值、1R 后移动止损的各种方向
- **跨周期推进**：上层周期推进一根时基础 K 线逐根结算的正确性、周期边界对齐、步内事件回溯的顺序与完整性、播放遇事件自动暂停的触发时机
- **匿名化一致性**：主体与尾声段使用同一套变换参数，价格与时间连续
- **构建边界**：新 entry 的 pro 泄漏守卫（沿用现有 `proLeakGuard` 断言）

## 13. 实施分期

本设计的范围超出单个实现计划，按以下里程碑推进，每期各自成计划：

**M0 — 前置实测** ✅ 已完成（2026-07-25）
结论见 §3：五档周期均可回溯至 2018 年，极端行情可用，池子时间广度不受限；新增约束是单次 1000 根上限与分页拉取要求。原计划中「某档深度不足则延后或降级」的分支不需要了，五档全部保留。

**M1 — 引擎泛化**（`packages/bench`，公开仓）
§4 全部改动 + 新增「照现价立刻进」成交路径。产出可被 bench 自身与训练器共用的多周期 episode 引擎。此期结束时 bench 现有测试须全绿。

**M2 — case 池管线**（`apps/pro`，无 UI）
采样、两道闸、匿名化含尾声段、audit、存储、补货。以 CLI 或脚本形式验收：能产出一批合规 case，且泄漏测试（§12）通过。

**M3 — 训练局**（独立 entry + UI）
新 entry 与窗口、游标截断的图、拖拽下单、纪律拦截、推进控制、收盘结算基础版。此期结束即可完整刷盘，但没有 AI 陪练。

**M4 — AI 陪练与标注**
pipeline 数据注入改造（本设计最大的单项工程）、锁定顺序、自动判定、人工标注策略。

**M5 — 复盘与统计**
复盘页重放与尾声段、统计面板、教训沉淀通道、回流导出（评测集与偏差报告）。

M3 结束时功能已可独立使用，M4 / M5 是增量。若需砍范围，从 M5 往前砍。

## 14. 明确不做

- 人机竞技排行榜（本设计定位为个人训练场）
- 日线 / 周线档
- few-shot 反例库
- fine-tune
- 自动写入 `journal/`
- 多笔持仓 / 分批加减仓（会失去三价强制，训练器退化为手感玩具）
- 「不盲」开关（对美股大盘的记忆过强，露出真名即开卷）
