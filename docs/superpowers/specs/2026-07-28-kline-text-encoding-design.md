# 喂给模型的 K 线改用紧凑文本编码 —— 设计

> 2026-07-28 · 盲盘训练 P0（共享原语，P2 依赖）

## 1. 背景

现在所有喂给模型的 K 线都是 `JSON.stringify` 的原始对象。实测一根真实 bar：

```json
{"time":"2026-07-20T03:30:00.000Z","open":559.99,"high":561.16,"low":559.77,"close":559.77,"volume":153}
```

**104 字节**。同一根写成 CSV `03:30,559.99,561.16,559.77,559.77,153` 是 **37 字节**，省 64%。

用磁盘上真实的盲盘案例（`swing-ASSET090-2017-12-21-01.json`）整份实测：

| 序列 | 根数 | JSON | CSV | 省 |
| --- | --- | --- | --- | --- |
| 5m 回看 | 210 | 26,839 | 8,091 | 70% |
| 15m 回看 | 250 | 32,287 | 9,989 | 69% |
| 1h 回看 | 104 | 13,595 | 4,438 | 67% |
| 回放 | 156 | 20,402 | 6,416 | 69% |
| replay.rollups | — | 11,935 | 删（可从回放推出） | 100% |
| **整份** | | **109,351 字节** | **33,024 字节** | **70%** |

> **本表只用字节，不换算 token。** 初稿按 4 字符/token 给出过 27.3k → 8.3k 的估算，2026-07-28 实跑证伪：同一份负载实际是 19,245 token。那个系数是英文散文的经验值，而这里几乎全是密集小数——`100.67` 会切成好几个 token。
>
> **压缩比不受影响**，字节和 token 同比例下降；错的是绝对值。下表的 token 数同属早期估算，仅用于比较量级，不可当作实测。

按调用点估算的收益：

| 调用点 | 规模 | 现在 | 之后 |
| --- | --- | --- | --- |
| `fetch_kline` 工具 | 上限 500 根 | ≈13k token/次 | ≈4.7k |
| reassess datapack | 3 档×60 + 日线 60 | ≈6.2k token/次 | ≈2.2k |
| comment datapack | 48 根 m5 + 日线 | ≈1.5k | ≈0.5k |
| bench episode mock | 每步一次 | 同量级 | — |

**但省 token 不是这件事最大的收益。** 见 §2。

## 2. 两个静默错误来源

改编码顺带解掉两个现在就在发生、且不会报错的问题。

### 2.1 时间戳是 UTC，模型每根都要自己换算

时间戳形如 `2026-07-23T06:20:00.000Z`，实际是 ET 凌晨 2:20。模型每读一根都要做「UTC → ET（还要判断夏令时）→ 落在哪个时段」。

实测一张真实的 NVDA 5 分钟图，1000 根 bar 的时段分布：

| 时段 | 根数 | 占比 |
| --- | --- | --- |
| 盘前 / 隔夜 | 352 | 35% |
| 盘中 | 312 | **31%** |
| 盘后 | 336 | 34% |

**只有三成是盘中。** 模型把盘前的稀薄成交当成盘中放量，输出看起来完全合理，没有任何迹象提示读错了。

### 2.2 指标是平行数组，靠下标对齐

datapack 现在给的是 `bars: [...]` 加 `macd: { dif: [], dea: [], hist: [] }` 四个平行数组，模型要靠下标才能知道第 37 根 bar 配哪个 dif。对齐错和时区错是同一类：静默。

两个问题的共性是**让模型做推理工作**。编码器把它们变成**读取工作**：时区转换在编码时做一次（确定性），指标并进同一张表（对齐变成结构性的）。

## 3. 目标与范围

**目标**：给出一个共享的 K 线文本编码器，所有喂给模型的 K 线与按 bar 对齐的指标统一走它。

**这期做**

- 共享编码器（`packages/shared`）
- 四个调用点全部切换
- prompt 同步
- 三层验证（§8）

**非美股标的**

时区**不得硬编码 ET** —— 本仓支持 HK / A 股 / 新加坡标的，对 `700.HK` 用 ET 是直接的错误。规则是时区跟随标的所属市场，元信息行写明实际用的是哪个时区。

但**时段标注这一期只做美股**：港股有午间休市，A 股的时段结构也不同，各做一套划分是另一个量级的工作，而本仓默认市场是 US（TD-LANG-03）。非美股标的的退化行为是**不出 `## 段头`，每行带完整的本地日期时间**，元信息行注明「未分时段」。宁可退回啰嗦但正确的形式，也不要输出一个按美股时段错误切分的港股序列。

**这期不做**

- 不做非美股的时段划分（见上）
- 不动图表数据文件（`journal/charts/data/*.json`）与 API 响应 —— 那些是给界面和存档用的，不是给模型看的
- 不动 `fetch_news`、chart drawings 等不含 K 线的工具返回
- 不动 `bench/mock/sandbox.ts` 的沙箱变量注入 —— 那是给 JS 代码读的，不是给模型读的

**切换方式：硬切。** 不保留运行时的格式开关，JSON 路径直接删除。对照实验挪到合并之前完成（§8.3）。

## 4. 编码格式

```
# NVDA.US 5m · ET · 全时段 · 1000 根
# time,o,h,l,c,v,dif,dea,hist
## 2026-07-21 pre
04:00,178.20,178.35,178.10,178.28,1204,,,
08:40,178.55,178.90,178.41,178.77,10256,0.412,0.388,0.048
## 2026-07-21 reg
09:30,179.05,179.88,178.92,179.60,842301,0.455,0.401,0.108
## 2026-07-21 post
16:05,179.44,179.50,179.30,179.35,22140,0.398,0.410,-0.024
```

约定：

- **第一行元信息**：标的、周期、时区、是否过滤、根数
- **第二行列名**：随实际列数变化（无指标时只有 OHLCV）
- **段头 `## 交易日 时段`**，时段三选一 `pre` / `reg` / `post`
- **交易日用 `marketDate` 而非自然日** —— 隔夜盘跨零点，ET 周四凌晨 2:20 属于周四的盘前
- **空字段等于 null** —— MACD 前 25 根没有值就留空
- **日线 / 周线**没有 `HH:MM` 也没有时段：整行用完整日期，不出段头

### 4.0 时段的确切边界

美股按 ET 划分：

| 标记 | 区间（ET） |
| --- | --- |
| `pre` | 04:00 至 09:30 之前 |
| `reg` | 09:30 至收盘 |
| `post` | 收盘至 20:00 |

20:00 至次日 04:00 的隔夜盘归入**下一个交易日的 `pre`**，与 `marketDate` 的归属保持一致 —— ET 周四凌晨 2:20 是周四的 `pre`，不是周三的延续。

**半日市**（感恩节次日等提前收盘的交易日）收盘在 13:00 而非 16:00，`reg` 与 `post` 的分界随之前移。不能把 16:00 写死 —— 代码里已有半日市的概念（`blindCaseBuilder.ts` 的 `NYSE_HALF_SESSION_MINUTES = 210`），实现时复用同一判定，不要另起一套。

### 4.1 指标并入同一张表

按 bar 对齐的指标（当前是 MACD 的 dif / dea / hist）作为列追加，不再单独成数组。

非按 bar 对齐的指标（如案例里的 `sma20` / `sma50` / `sma200` 单值）不进表，留在外层，只按 §5 的规则收精度。

**`hist` 保留，不推给模型算。** 虽然 `hist = 2 × (dif − dea)` 完全可推（`packages/core/src/analysis/indicators.ts:59`），但柱子正是交易者直接读的那个量。我们喂指标的全部理由就是模型算术不可靠，为省 33% 又把它推回去是自相矛盾的。

## 5. 精度规则

| 项 | 规则 | 理由 |
| --- | --- | --- |
| 价格 | ≥ $1 留 2 位小数，< $1 留 4 位 | 与美股 tick 规则一致 |
| 成交量 | 取整 | 小数是匿名化缩放的产物，无实际含义 |
| 指标 | 4 位有效数字 | 固定小数位不行：$500 的标的 dif 约 2.5，$5 的标的 dif 约 0.012 |

现状的浪费集中在精度：`0.5974505684651916`（18 位）、`99.74378886000002`（明显的浮点尾巴）。

## 6. 时段过滤

编码器提供过滤参数，**默认全部保留**。

**默认必须全保留**：隔夜跳空经常就是全部剧情（盘后财报、隔夜消息都在那 69% 里）。默认丢掉它们，模型会把跳空读成连续走势，且无迹象可循。`trading-discipline` 的 TD-VERIFY-01 第 3 条要求拿现价与盘前高点比较 —— 只有盘中数据时这条根本执行不了。

**但参数要有**：算 MACD、均线时掺入稀薄的隔夜 bar 会失真；面向「今天盘中走势如何」的问题，砍掉 69% 的量是白送的。

**过滤生效时元信息行必须写明**（如「仅盘中」）。否则过滤过的序列与完整序列外观一致，模型会把跨日的两根盘中 bar 当作连续 —— 这是过滤最危险的副作用，一行说明即可消除。

**过滤参数暴露给 `fetch_kline` 工具**，由模型自行选择。它问「今天盘中量能如何」时可以自己要盘中数据，省下的 token 由它自己挣，比在代码里替它猜更合理。

| `apps/pro/src/bench/mock/index.ts:62` | bench episode 的 `fetch_kline` 复制品 |

### 7.1 pack 保持 JSON 外壳，K 线部分是字符串字段

datapack 除 K 线外还有报价、资金流、新闻、评论、日内关键位 —— 这些天然是键值结构，转成表格反而难读。故 pack 仍是 JSON 对象，仅把 K 线与按 bar 对齐的指标换成一个字符串字段，内容是 §4 的表。

原则是：**同类数据统一格式，不同类数据各用各的**。K 线与 MACD 合并成表，是因为它们本就是按 bar 对齐的同一批数据；报价与新闻不是。

同一种数据出现两种格式才是真正的危险（模型会把两边字段对错位），不同种数据格式不同不会引起混淆。

## 8. 验证

硬切之下，对照实验挪到合并之前，分三层。

### 8.1 编码器 golden 测试

固定输入断言输出字符串。边界必须覆盖：MACD 前段的 null、跨交易日、跨时段、< $1 的价格、日线（无时段无 `HH:MM`）、空数组。

### 8.2 模型读取自检

喂一段 CSV，问「第 37 根的最高价是多少」「哪一根的 MACD 柱由负转正」，断言答对。

这层最便宜也最直接，能拦住绝大部分格式歧义，且以后换模型时可重跑。

### 8.3 合并前的一次性对照

在一个**不进主干的临时提交**里让两种编码并存，同一批 episode 数据各跑一遍 bench，比分数。不劣化才删除 JSON 路径并合并。

这是唯一能回答「模型的判断有没有变差」的手段。它只存在于开发过程中，不进入发布产物 —— 硬切的要求不受影响。

**注意**：本改动会使此前的 bench 跑分与线上复评结论不再可比（同一盘面、同一模型，喂 JSON 与喂 CSV 不保证得出相同判断）。仓库中没有存档的 baseline 数据（`packages/bench/src/baseline/` 是跑分代码而非结果），故实际代价是「以后重建参照」，而非作废既有资产。

## 9. prompt 改动

`packages/core/src/ai/runtime/prompts.ts:88` 与 `:116` 现在明确描述「you receive a **JSON snapshot** with live quotes, **five-minute bars and MACD**」，直接描述了被改动的对象，必须同步。`:118` 的「图上有什么」一条提到 MACD 与均线，需确认表述仍然成立。

教模型读表分两层，两层都要：

- **表头自描述**（在数据里）—— 列名、时区、是否过滤写在 payload 顶部。即使某处 prompt 漏改，模型仍有完整线索
- **system prompt 一小段**（在提示里）—— 只解释两个约定：`## 日期 时段` 的分段含义、空字段等于 null

两层失效的方式不同：prompt 会漏改，表头不会；但表头解释不了「为什么盘前量能不能与盘中比」这类语义。

## 11. 与 P1 / P2 的关系

- **P0（本文）** 与 **P1（补货搬进 app，`2026-07-28-training-case-pool-refill-design.md`）** 相互独立，先后不限
- **P2（AI 精选闸）** 依赖两者：需要 P0 的编码器压缩输入，需要 P1 的 kernel 内模型访问

P2 已定下的约束见 P1 spec §11。其中与本文相关的一条：精选闸喂给模型的是**匿名化之前**的真实盘面，价格是真实股价（如 GM 的 $34.52），比案例文件里六位小数的缩放价格更短，故 §1 表格中的字节数对 P2 而言是保守估计。P2 的实测 token 见其 §8。
