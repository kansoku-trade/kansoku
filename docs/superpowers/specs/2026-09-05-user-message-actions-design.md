# 用户消息操作条（复制 / 编辑 / 重试）

日期：2026-09-05
状态：已确认
范围：三类 AI 对话共用（chart / research / assistant）。前端挂在 `ConversationTranscript`；后端在现有 `postMessage` 上加「替换最后一条」语义。

## 背景

助手气泡已经有 `MessageActions`：复制 + 重试，只出现在最后一条已完成的助手回复底下，而且是常驻。用户气泡只有文字，没有操作。

现在助手上的「重试」会再追加一条同样的提问，对话里会出现两条一模一样的用户气泡。接到用户侧之后，两边都改成「清掉这条后面的内容再发」。

## 已确认的 UI 决策

| 维度 | 决策 |
| --- | --- |
| 操作 | 复制、编辑、重试。不做删除。 |
| 出现方式 | 悬停出现，贴在气泡下方、右对齐。图标无字，系统 tooltip 写「复制 / 编辑 / 重试」。 |
| 哪些消息 | 任何用户气泡都能复制。只有**最后一条用户提问**能编辑、能重试。 |
| 编辑位置 | 就地改气泡。底部输入框在编辑期间关掉。 |
| 好不好发现 | 全部靠悬停，不常驻。最后一条也不例外。 |
| 确认框 | 复制、编辑发送、重试都不弹确认。 |

助手气泡的操作条保持现状：最后一条已完成回复上常驻复制 + 重试，不改成悬停。

## 平时长什么样

用户气泡仍然右对齐、底色 `backgroundElement`。每条用户消息底下预留一行，高度等于现有 `MessageActions`（`margin-top: 4px` + `controlHeight`），图标默认看不见。悬停或键盘 focus 到按钮时显示。预留高度是为了悬停时不把后面的回复顶下去。

- 更早的提问：只出复制。
- 最后一条：出复制、编辑、重试。
- 复用 `MessageActions` 的按钮样式（13px 图标、静音色、悬停变主色、按下 `scale(0.96)`），右对齐。不要另做一套。
- 键盘 tab 到按钮时，即使没悬停也显示。

「最后一条用户提问」= 记录里从后往前第一条 `kind === 'user'` 且有正文的气泡。它后面可以跟着助手回复、工具行、画布或报错。

驾驶舱侧栏、助手页、研究对话共用这一套。

## 编辑

只有最后一条能进编辑态。正在回答时不能进入。

点「编辑」之后：

- 气泡变成多行输入框，底色不变，加上和现有输入框一样的焦点描边。
- 悬停操作条换成右下的「取消」和「发送」。发送用强调色，和底部发送键同一套。
- 底部输入框暂时关掉，避免两条发送路径。助手页的待发队列在编辑期间不准出队。
- Enter 发送，Shift+Enter 换行，Esc 取消。和现有 composer 一致。
- 取消：字还原，回到普通气泡。
- 发送：这条换成新文本，清掉它后面的所有内容，立刻按新文本重跑。
- 空内容（去空白后为空）不能发送，发送键不可点。

若编辑的是会话第一条提问，标题按现有 `titleFromText`（前 40 字）重算。助手会话若已经有模型生成的标题，沿用现有 `shouldAssignGeneratedTitle` 判断，不覆盖生成标题。

同时只允许一条消息处于编辑态。

## 复制

任何用户气泡都能拷原文（纯文本，不是 Markdown）。正在回答时也可以。

图标闪成对勾，1200ms 后回到复制图标。行为和助手侧 `MessageActions` 相同。

复制只走剪贴板，不打后端。

## 重试

一点就跑，不弹确认。清掉最后一条用户提问后面的所有内容（助手回复、工具行、画布、报错），同一段文字立刻再发。界面效果和刚发送完一样：用户气泡留着，下面出现思考占位，然后流式输出。

助手气泡上现有的「重试」改走同一条路径，不再追加一条重复的用户提问。

## 正在回答

- 编辑、重试仍占位但灰掉不可点。复制可点。
- 打断只用底部停止键，气泡上不另放停止。
- 已经打开的编辑态在回合开始前必须先关掉；正在回答时进不了编辑。

## 接线

### 前端

`MessageActions` 增加可选的 `onEdit`，以及对齐方向（助手左、用户右）。用户气泡在 `TranscriptBlockView` 的 `user` 分支里渲染它。悬停显隐由用户行的 CSS 控制（默认看不见，悬停 / `:focus-within` 显示），组件本身仍是那三个按钮，不另做一套。

`ConversationTranscript` 算出最后一条用户气泡的下标，以及是否正在回答。编辑态放在 transcript 内部：

- `onReplaceLast(text: string)` 交给 `useChatSession`
- 编辑中对外暴露「composer 该关掉」，由 `ChatDock` / `AssistantConversation` / 研究侧栏把 composer 设为 disabled

`useChatSession.retryLast` 改为走替换而不是追加。新增 `replaceLast(text)`：编辑发送时调用。失败时 `reload()` 拉回服务器上的原记录，hint 用现有发送失败文案。

乐观更新：替换时先在本地删掉最后一条用户提问后面的行，若文本变了就改这条用户气泡的正文，然后按现有 `send` 进入 busy / 流式。不要再插一条新的用户气泡。

### 后端

三类对话的 `postMessage` 增加可选字段 `replaceLast?: boolean`，默认 `false`。现有追加行为不变。

`replaceLast: true` 时，在开跑之前、同一事务里：

1. 会话正在回答 → 409，和今天 busy 相同。
2. 找不到用户提问 → 409。
3. 删掉最后一条用户提问之后的全部消息。
4. 若新文本和原文本不同，更新最后一条用户提问的 payload，并把 `updatedAt` 写成现在。
5. 然后走现有 `runChatTurn`（不要再 append 一条用户消息；用户消息已经在库里）。

实现放在共用的 `conversationStore`，chart / research / assistant 三份 store 一起有。不要给三条对话各写一份删除逻辑。

合约、HTTP、desktop IPC 同步改。前端三个 `conversationAdapters.send` 增加同一可选参数。

## 不做的事

- 不给历史提问做编辑 / 重试（会截断长对话）。
- 不做删除、点赞、分支会话。
- 不把助手操作条改成悬停。
- 不在气泡上放停止键。
- 不新开独立的 retry / edit 路由。

## 验证

1. 后端：`replaceLast` 清掉最后一条用户提问之后的内容；文本不变时用户气泡仍是一条；文本变了时 payload 更新；busy 时 409；无用户提问时 409；三条对话各有一条覆盖。
2. 前端：最后一条悬停出三个图标，更早的只有复制；编辑态键盘与 composer 互斥；正在回答时编辑 / 重试灰掉；重试后记录里不会出现两条相同的用户提问。
3. 桌面端肉眼：驾驶舱侧栏、助手页、研究对话各走一遍复制 / 编辑 / 重试，确认悬停不把后面回复顶下去。
