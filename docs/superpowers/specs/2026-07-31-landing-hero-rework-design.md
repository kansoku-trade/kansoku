# Landing 首屏重排：品牌名当标题

日期：2026-07-31
范围：`apps/site` 首页首屏（`HeroEvidence.astro` / `hero.css`）

## 为什么改

改之前的首屏（2026-07-30 那次文案重写之后）是这样：

- 眉标：`个人市场研究工作台 · macOS`
- 主标题：`看盘时怎么想的，盘后还能找回来。`
- 副文：`看盘、画线、记录判断和跟踪结果，都在同一个工作区完成。行情从你的数据源读取…`
- 右栏：会动的证据图（节点图 + Bull/Base/Bear 判断卡片 + 粒子）

两个问题：

1. **看不出这是干嘛的。** 主标题是一句价值主张，不是品类说明。
2. **标题里没有产品名。** 品牌只在顶部导航和终端外壳里以小字出现。

## 决定

首屏顶部改成三段递减：**眉标（品类标签）→ 通栏品牌字标 → 一行品类句**，一条 hairline 收口；下面才是原来的两栏。右栏的证据图**保持不动**。

## 一、版式骨架

`.hero-evidence-shell` 从「两栏 grid」改成「纵向两块」：第一块 `.hero-mark` 是通栏字标区，第二块 `.hero-evidence-grid` 才是原来的两栏。

```
┌─ hero-evidence-shell (flex column) ─────────────────┐
│  个人市场研究工作台                                  │
│  K A N S O K U  観測          ← 通栏，跨满 1200px    │
│  在 Mac 上看盘、记录判断、跟踪结果。                  │
│  ─────────────────────────────────────────────      │
│  ┌── 左栏 46% ────────┐  ┌── 右栏 1fr ──────────    │
│  │ 副文…              │  │  证据图（节点 + 判断卡）  │
│  │ [下载] [看工作流]  │  │  ——— 保持不动 ———        │
│  │ 免费行 / note      │  │                          │
│  └────────────────────┘  └──────────────────────    │
└─────────────────────────────────────────────────────┘
```

## 二、通栏字标

`<h1>` 内容为 `KANSOKU 観測`。

- 字体 `var(--mono)`，字距 `0.16em`（≤900px 收到 `0.08em`），字号 `clamp(30px, 7vw, 100px)`
- `.hero-mark` 下面一条 hairline，呼应终端外壳的细线语言
- `観測` 用 `<b>` 包住，颜色 `var(--accent)`（琥珀），与导航 `.nav-name b` / `.chrome-brand b` 的处理一致

## 三、文案（最终稿）

```
个人市场研究工作台                    ← 眉标

KANSOKU 観測                          ← h1

在 Mac 上看盘、记录判断、跟踪结果。    ← .hero-lede，clamp(19px, 2.5vw, 32px)
─────────────────────────────────────

多周期 K 线、画线、SEPA、盘中记录和历史复盘都在同一个工作区。
行情走你自己的数据源，指标在本机计算，研究记录以文件形式存在
本地；需要时再让 AI 参与查询和复评。

[ 下载 macOS 版 v{version} ]  [ 查看实际工作流 ↓ ]
多周期看盘、复评和基础对话可免费使用，无需注册 Kansoku 账号。比较免费版与 Pro →
Apple Silicon Mac · 需安装并登录 longbridge CLI · 首次启动时右键应用并选择「打开」
```

改动点：

- 眉标去掉「· macOS」。Mac 在品类句里出现一次、底部 note 里还有「Apple Silicon Mac」，首屏说三遍太碎。
- 品类句是新增的 `.hero-lede`，不是 `<h2>`——它是 h1 的同位语，不该开新的标题层级。它放在 `.hero-mark` 里通栏，不进左栏：挤进 480px 的窄栏会折成两行且断在「记录」中间。
- 副文去掉了「看盘、画线、记录判断和跟踪结果」这半句（与品类句重复），改成先报功能清单、再交代数据归属。
- CTA、免费行、note 三行原样不动。
- 两栏比例从 `minmax(420px, 560px)` 改成 `minmax(0, 46%)`，让证据图那一栏随视口按比例长大，中等宽度下不被挤扁。

## 四、试过但否掉的：右栏换真机截图

中途试过把右栏的节点图换成 `public/landing/app-cockpit.webp`（1600×1000，左边多周期 K 线带 EMA/MACD、右边短线方向判断与情景概率），向右出血到视口边缘。

**否掉了。** 静态截图把原本会动的证据图整块盖住，首屏的动效没了，得不偿失。右栏维持 `scenes/hero.ts` 驱动的节点图 + 判断卡片 + 粒子不动。

顺带记一笔（本次未处理）：`public/landing/` 下 6 张真机截图目前只被 `DensityWall.astro` 引用，而首页早就不渲染那个组件了——这些图在首页处于闲置状态。要不要在首屏之外的段落用上，另议。

## 影响

- **JS 无牵连。** `scripts/landing/` 下没有任何模块引用 `hero-title` / `hero-sub` / `hero-eyebrow`，`scenes/hero.ts` 只认 `[data-hero-scene]` 及卡片内的 data 属性，这些结构原样保留。
- **meta 不动。** `index.astro` 的 `<title>` 与 `description` 本来就准确，也不与新副文冲突。

## 验证（已跑）

- `pnpm typecheck` / `pnpm test`（11 文件 102 用例）/ `pnpm build` 全绿
- 浏览器实测 320 / 360 / 375 / 390 / 768 / 1024 / 1280 / 1440：字标与品类句在每档都是单行，首屏无横向溢出
- 证据图在 1440 下确认仍然挂载（`.hero-evidence-scene` 拿到 `is-live`，判断卡片 `is-visible`）
